# Harness Enhanced

## 快速安装

在 GitHub 用户 `Leo19990721` 的 [Harness Enhanced v0.1.6 Release](https://github.com/Leo19990721/dsh-harness-enhanced/releases/tag/v0.1.6) 下载 `local-dsh-harness-enhanced-0.1.6.tgz`（不要选 Source code 压缩包）。在 DSH 「插件 → 添加插件」粘贴该 `.tgz` 的绝对路径即可，不需要把网页或下载链接的内容直接传给命令行执行。适配基准为 DSH `0.2.2-rc.5`。

办公工作规则见 [办公版 AGENTS.md](docs/office-AGENTS.md)。Windows 批量部署用 [install-plugins.ps1](docs/install-plugins.ps1)：默认只下载、校验并暂存四个版本固定的安装包。若确认要安装，请先完全退出 Desktop，再加 `-Install`；脚本不会自动打开 Desktop。

不克隆仓库时，可先[查看脚本](docs/install-plugins.ps1)，再用 PowerShell 7 运行下面一行。去掉 `-Install` 即只下载和校验。

```powershell
$script = Join-Path (Get-Location).Path ('dsh-install-plugins-' + [Guid]::NewGuid().ToString('N') + '.ps1'); Invoke-WebRequest -ErrorAction Stop 'https://raw.githubusercontent.com/Leo19990721/dsh-harness-enhanced/v0.1.6/docs/install-plugins.ps1' -OutFile $script; & $script -Install
```

## 打开聊天中的本地目录

在本机 Windows DSH 聊天中，点击绝对路径的目录链接会在资源管理器打开。旧消息中的 `file:///` 本地链接也能使用：文件仍走 DSH 预览，目录走资源管理器。网页链接不变；远程、网络共享和重解析点不走这条本机打开路径。

## 一键展开会话

在 DSH 左侧的工作区列表里，点一个文件夹下的「展开其余 N 个会话」，即可显示这个文件夹在当前筛选下的所有会话。原来的「收起」按钮、默认可见行、置顶、排序和筛选规则保持不变。其他文件夹不会跟着展开。

在 DSH 的「插件」页可启用或停用 Harness Enhanced。停用后，后续点击恢复原生的每批五条。已经展开的列表仍可以用原来的「收起」按钮恢复。

本功能仅在客户端接续原生按钮的展开操作。它不新增界面控件，不修改 DSH 安装文件或会话数据，也不发送额外网络请求。适用于使用原生展开按钮的分组列表；单列表和搜索结果保持原样。

## 移除左侧栏「更多」

启用插件后，左侧导航下方的「更多」不再显示。已注册的面板入口直接留在侧栏，原有顺序不变；原先收在「更多」里的面板入口也会显示。会话顶部的「更多会话视图」和右侧栏的「更多工具」不受影响。

停用插件后，左侧栏恢复原来的「更多」菜单和固定入口操作。

## 恢复失败消息

切换模型时，如果上下文压缩失败，且一条普通文字已从发送队列取出、尚未进入对话，插件会在「处理失败」下显示「复制原文」。当前会话空闲、输入框为空且可编辑时，还会显示「放回输入框」。放回后可以先检查或修改，再决定是否发送。已有草稿、引用和附件保持原样。

重新打开会话后，仍可从已有记录找回。当前只支持由打开页面的本机 Host 保存、且有完整压缩记录可核对的失败；会话 ID 相同的远端记录不会匹配。主动取消、已进入对话、含附件、同时认领多条输入或无法核实的情况保持原样。复制的是 DSH 收入队列的原文。插件只向拥有本机 Host 所有者权限的客户端返回匹配文字，不另存消息、不改历史、不自动发送。

## 上下文压缩

内置的标准、PTC、Cordis、极简预设启用新策略。它不调大模型窗口，也不从每次聊天请求里扣 65,536 token 给摘要。以 Codex 的 Astra 272,000 为例，可用输入预算是 258,400，预计输入达到 244,800 才考虑自动压缩。低于这条线时，不改写历史。支持独立输入限制的 Google Gemini 路由直接使用其输入窗口；共享窗口的 DeepSeek 和中转路由照常给实际输出上限留空间。

到线后先试算一批旧工具结果能省多少。只有裁剪后不超过可用输入的 75%，才提交这些修改：保留头尾和可识别的文件路径，完整结果仍在原日志里。裁剪不够就一条也不改，优先用同会话、同路由的原历史前缀做摘要，尽量保留缓存，目标是让剩余输入回到预算的 60%。压缩只在记录确实缩短后重建普通请求，不重复提交新消息。服务端真报上下文溢出时，另外允许一轮缩减重试；没有可压内容会提示如何减负。

`/compact` 仍走原生命令和原有设置；`read`、终端和结果溢写仍用 DSH 的现有上限。Google 订阅的 Antigravity CLI 自管历史，不用 DSH 的对应历史触发新策略；订阅包提供的「写作模式」及其他自定义预设未改。切换到更小的窗口且旧历史已经过线时，保留 rc.5 的发送前检查，所以原来的「复制原文 / 放回输入框」仍可用。

新策略加载失败时，该预设回到原生压缩。停用或卸载本插件会移除预设覆盖，之后启动的会话使用原生策略；运行中的会话按 DSH 规则保留已绑定的预设版本，完整重启 DSH 后统一切换。只想恢复某个内置预设的原生压缩、保留其他增强时，可在该预设的 `compaction` 组中给 `compaction-basic` 行设置 `config: { enhanced: false }`。

## 开发

以 DSH `0.2.2-rc.5` 的原生接口为适配基准。侧栏只接续同一个按钮、同一个分组且可见行确实增加的展开操作；未识别的界面保持原生行为。消息恢复使用 `conversation.chat.turnTail` 和 Connection 所有者专用的只读路由，复用 Session 历史的原生读取方式，向客户端最多返回匹配的一条文字。插件只检查 25 万个事件以内的日志。会话尚未载入内存时，仅查找已确认采用当前格式、磁盘文件不超过 8 MiB 的记录；实际解压由 DSH 处理。

改完客户端源码后运行 `node build.mjs`。`pnpm test` 检查客户端生成结果和策略单测；Windows 上可运行 `pwsh -File tests/run-installed-compaction.ps1`，用已安装的 DSH 原生循环和假适配器测试压缩，不调用模型服务。`build-compaction.mjs` 用同一版 DSH 的预设生成覆盖，只更换压缩后端一行。

用 `pnpm pack --pack-destination .local-install` 生成安装包，在 DSH「插件 → 添加插件」粘贴 `.tgz` 的绝对路径。替换已安装版本后，若管理器提示需要重启，等手头任务结束再退出并重新打开 DSH；用新会话验证。要回退但保留三项原有增强，添加 `.local-install/local-dsh-harness-enhanced-0.1.3.tgz`，然后重新打开 DSH。
